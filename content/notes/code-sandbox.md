## What It Is
The Code Sandbox is an isolated execution environment for running code generated by the coder agent. When the AI writes a Python or JavaScript program and needs to test it, the code runs inside a Docker container (a sealed virtual environment) rather than directly on your machine. The container has no access to the internet, no access to your files, and strict CPU and memory limits. Whatever happens inside the container, your host machine is safe.

## Why It Matters
Letting an AI execute arbitrary code directly on your computer is a significant security risk. Even a well-intentioned mistake could delete files, install software, or make unwanted changes. The Code Sandbox means the coder agent can run and verify its own code during development without any of that risk. If the code crashes, hangs, or does something unexpected, the container is thrown away with no lasting effect. This is what enables the coder agent to be genuinely useful rather than just a code-suggestion tool.

## How It Works
The Sandbox is built on Docker — a widely used technology for running applications in isolated containers. When the coder agent needs to execute code, it sends the code to the Sandbox via an internal API call. The Sandbox spins up a fresh container from a pre-built image (Python or Node.js depending on the language), runs the code inside it, captures the output (stdout, stderr, exit code), and returns the result to the agent.

The container is configured with strict security limits: no network access (`--network none`), read-only filesystem except for a temporary working directory, half a CPU core (`--cpus 0.5`), 256 MB of memory, and a 30-second execution timeout. After the code finishes (or times out), the container is automatically destroyed — nothing persists.

Two Docker images are pre-built: `Dockerfile.python` for Python code and `Dockerfile.node` for JavaScript/Node.js. A `build.ps1` PowerShell script builds both images on first setup. The Sandbox exposes a health endpoint (`GET /sandbox/health`) and a run endpoint (`POST /sandbox/run`) that the Orchestrator and Tool Loop use.

## Key Files

- `orchestrator/sandbox/Dockerfile.node` — Node.js sandbox image
- `orchestrator/sandbox/build.ps1` — Image build script

## Open Questions / Known Gaps
- The memory limit (256 MB) and CPU limit (0.5 cores) are intentionally conservative. For data-heavy tasks, these may need to be raised selectively — which would require a configurable override mechanism.
